# Design: media-core

Sources of truth: `backend/src/main/resources/db/migration/V001__initial_schema.sql` (schema), `api/openapi.yaml` (contract), `datasource` published API (`MediaResolver`, `BookRef`/`MovieRef`, `BookItem`/`MovieItem`, `CatalogException`). Contract field names: `isbn`, `originalTitle`, `tvStatus`, `author`, `source`, `externalId`, `externalLink`, `coverUrl` (books), `posterUrl` (movies), `seasonCount`, `isFavorite`. Revised 2026-11-19 to match the Phase 2 tree and the ROADMAP (source enum, `{id, sourceUrl}` create).

## 1. Decisions and trade-offs
| Question | Decision | Why / rejected |
|---|---|---|
| Filters, sort, list search, counts | Client-side over the full per-user list (TanStack Query cache). List endpoints take no filter parameters. | One implementation; `Intl.Collator` title sort (roadmap Q9); device-local state. Server filtering rejected (two implementations, needs network). |
| One table or two | Two (`books`, `movies`). | Different fields; Phase 5 resource types. |
| Primary key | `(user_id, id)`, `id` = client UUID. | User B posting A's UUID must not collide with A's row: cross-user is 404 or an own row by construction. |
| Source identity | Closed enum column `source` (`draft`/`open_library` for books, `draft`/`tmdb` for movies, the contract's `BookSourceId`/`MovieSourceId`) plus `external_id`; identity is `(source, external_id)` (movies: `(source, type, external_id)`). A draft is an item with `source = draft`, never inferred from `externalId` (every item has one). | ROADMAP domain. Replaces the earlier "implicit source" idea. One unique index per table serves provider items and drafts. |
| Draft `external_id` | The title key: NFC, strip, `toLowerCase(Locale.ROOT)`, NFC (`media.TitleKey`), computed by `media` from the item's title. NOT the draft ref's `externalId` (the datasource draft resolver keeps the typed text there, case preserved, because `resolve` rebuilds the title from it). | The unique index then dedupes drafts case-insensitively (iOS rule). Client twin `titleKey`, vectors in `api/test-vectors/source-urls.json` (`titleKey` block, restored from the shelf). ROADMAP wording "normalized title" is read as "case-folded normalized title". |
| Draft duplicate scope | A draft title is checked against ANY live title in the same list (movies: also original title), not only drafts (iOS rule, owner confirmed 2026-11-19). A real item is not blocked by a same-titled draft. | Draft vs draft = unique index; draft vs non-draft = service under the user lock. |
| Create | `POST {id, sourceUrl}` and nothing else; status `planned`, not favorite; the server recognizes the URL, never fetches it. Only the draft link is recognized in this change (see 11). | ROADMAP add-flow decision. No create-with-fields body anywhere. |
| Write style | REST: `POST` create, `PATCH /{id}` (status, favorite, tv `seasonCount`/`tvStatus`, `version` informational), `DELETE /{id}` tombstone. No `PUT`. Re-POST of a live id returns 200 with the stored item (body ignored). | Idempotency from the client id. |
| No-op writes | A PATCH equal to the stored content issues no UPDATE: no `version` bump, no `updatedAt` change (and, in Phase 5, no `change_seq`). | TV refresh "write only if changed" falls out. |
| Concurrency | Server LWW in arrival order, `version` +1 per accepted change set by the service; `PATCH.version` is informational. | Phase 5 adds the conflict flag on `/sync/push`. |
| Clock | `updated_at` from the server `Clock`. | Device clocks untrusted. |
| Delete | Soft: `deleted_at`, `version`+1, description nulled. Delete of a tombstone = 204; unknown or foreign id = 404; POST/PATCH of a tombstoned id = 410 and recreates nothing; live reads never return tombstones. | Keeps the Phase 5 tombstone model without a later migration (V001 is append-only after the first deploy). |
| Per-user write serialization | Each write first takes a per-user lock inside its transaction: `identity.UserLock` (concrete published bean of identity: a JPA `PESSIMISTIC_WRITE` row lock on the user's `users` row, propagation MANDATORY). | Needed for the duplicate checks no index can express (draft vs non-draft title) and the concurrent create race. The `users` table stays identity-owned: media calls identity's published `UserLock`, no raw SQL. The earlier `sync` module with a published `UserWriteLock` interface is dropped from Phase 3 (one consumer module, one implementation: YAGNI); Phase 5 introduces a shared lock in `sync` when `change_seq` ordering needs it across modules. See owner question 1. |
| `change_seq` | Not in Phase 3. Phase 5 adds the sequence, trigger function, `change_seq` columns and `(user_id, change_seq)` indexes to V001 in place. | ROADMAP: `change_seq` returns with `/sync/*`. `version` and `deleted_at` stay now because the contract and the tombstone semantics need them. |
| `immutable_field` | Not in Phase 3. The REST contract cannot express a change of source, ISBN, type or link, so the code is unreachable; it returns with the sync upsert in Phase 5. | Contract carries no dead codes. |
| ISBN | Stored normalized (no hyphens/spaces, uppercase X) by `media` from `BookItem.isbn` (datasource gives the provider's first non-blank value, not validated). A value that is empty after normalizing is stored as null. Search hits and details carry the provider's value; the client normalizes both sides. | One server implementation (store), one client twin `normalizeIsbn`. The datasource owner decision (no ISBN validation) is kept, so the contract has no ISBN pattern. |

## 2. Data
V001 gets `books` and `movies` back (restore list in section 9), keyed `(user_id, id)`. Columns as in the contract plus `source text NOT NULL`, `external_id text NOT NULL`, `external_link text NOT NULL`, `version bigint NOT NULL DEFAULT 1`, `deleted_at`, `created_at`, `updated_at`; books `isbn`; movies `original_title`, `tv_status`, `season_count`, `rating decimal(3,1)`. CHECKs: status, rating range (5 / 10), `source IN ('draft','open_library')` / `('draft','tmdb')`, external id length 1..1024, link length, provider id formats (`^OL[0-9]{1,12}W$`, `^[1-9][0-9]{0,9}$`), tv status, movie type, `draft` implies type `movie`. The same constraints as the shelf V001 (`refs/shelf/full`), minus `change_seq`.
Partial unique indexes over live rows (`deleted_at IS NULL`): books `(user_id, isbn)` where isbn not null and `(user_id, source, external_id)`; movies `(user_id, source, type, external_id)` (`type` is in the key: TMDb movie and tv ids are separate namespaces). Plus `(user_id, updated_at DESC)` and the `deleted_at` purge index as in the shelf. What an index cannot express (draft title vs a non-draft title/original title) is the service's job (section 3) and noted in the table comments.

## 3. Duplicate rules
- Book: same normalized `isbn`, or same `(source, externalId)` among live books. Service checks first to return `existingId`, and maps a unique violation of a lost race to the same 409.
- Movie: same `(source, type, externalId)`.
- Draft (either list): its title key equals the title key of any live item's title in that list (movies: also `originalTitle`), the item's own id excluded. Draft vs draft by the unique index too.
- Provider items: duplicate checks before the provider call and under the lock are `media-search` (design there, section 12).
The client mirrors the predicates in pure functions (`findByLink`, `findByIsbn`, `titleInLibrary`, section 7), shared with the add sheet.

## 4. Validation
Request bodies are validated by the generated Bean Validation (`id` uuid, `sourceUrl` 1..4096 with `@HttpUrl`, PATCH ranges). Stored content is built by the server (draft from the decoded link; provider data is normalized at datasource ingest and re-asserted by the V001 CHECKs), so there is no request-validator class: a stored-item violation is a server fault (`ProviderError` once providers exist; unreachable for a draft). PATCH: `seasonCount >= 0` and `seasonCount`/`tvStatus` only for `type = tv` (400 `validation`; V001 has no CHECK tying them to the type). A blank description is stored as null.

## 5. API
- Tags `books`, `movies`. Per resource: `GET` list (live items, bare array), `GET /{id}`, `POST`, `PATCH /{id}`, `DELETE /{id}`; operation ids `listBooks`, `getBook`, `createBook`, `updateBook`, `deleteBook` (movie twins).
- `POST` takes `CreateBookRequest`/`CreateMovieRequest` `{id, sourceUrl}`; responses 200 (id already live, before any URL inspection), 201, 400, 401, 409 `duplicate` (+`existingId`), 410 `gone`, 400 `validation` on `sourceUrl` (and, from media-search, 422 `source_not_found`, 409 `source_key_*`, 429, 502, 503, 504). `PATCH`: 400, 401, 404, 410. `DELETE`: 204, 401, 404.
- `Book`/`Movie` carry `id`, `userId`, `source`, `externalId`, `externalLink`, `version`, `createdAt`, `updatedAt`. Problem codes added: `duplicate` (+ `existingId`), `gone`. Cross-user ids answer 404.

## 6. Module layout (Modulith)
- `com.javanix.rwx.media`, `@ApplicationModule(allowedDependencies = {"identity", "datasource", "common", "api"})`. Grouped by feature, not one flat `internal` package: `media.book` and `media.movie` each hold their entity, key, repository (`...AndUserId` queries, extend `Repository<T,ID>`, not `JpaRepository`; the live-titles lookup is a derived query with an interface projection), source converter, service (takes the user id, no web types; returns the entity), controller (`BookController implements BooksApi`), MapStruct mapper (entity to API model) and its `AccountExportContributor` bean (`BookExport`/`MovieExport`), all package-private. What both truly share lives in `media.common` (internal to the module, not its published API; the module root holds no classes of its own): `TitleKey`, the `@MappedSuperclass` `MediaEntity` (shared columns, tombstone, version/updatedAt bump, status/favorite rule, blank description to null), `MediaRepository<E,K>` (`@NoRepositoryBean`: `findByIdAndUserId`, the live list, `saveAndFlush`) and the abstract `MediaService<E,R,I>` (create flow, get, list, delete; hooks `findByIdentity`, `isStorable`, `findDuplicate`, `newEntity`, plus `lockLive`/`save` for the subclass PATCH). `BookService`/`MovieService` are thin package-private subclasses; controllers, API mappers, exports and source converters are not shared (different generated types). `DuplicateException` (409 `duplicate` with `existingId`) and its handler live in `common` (`ProblemAdvice`); an unrecognized `sourceUrl` is an `InvalidRequestException` (400 `validation`, `errors[0].field` `sourceUrl`; owner decision 2026-11-19, no separate exception or code); there is no media advice class.
- `media` implements `AccountExportContributor` methods for books and movies (the default methods and the `AccountExport` arrays are restored in B1/B5).
- Architecture test: `media` repositories expose no unscoped `findById/findAll/deleteById/existsById`.
- YAGNI notes for implementers: no `BookRequest`/`BookResponse`/`BookPatch` records, no second mapper layer, no `BookDuplicateDetector` class (a private method of the service), no `sync` module, no source converter classes if `fromValue`/`getValue` on the generated enum suffices (a single `AttributeConverter` per enum only if JPA needs it).

## 7. Frontend design
- Online-first, no Dexie. Single seam `features/media/repository.ts` (list/create/update/delete per kind over the generated client); TanStack Query hooks (refetch on mount/focus/reconnect), mutations update the cache. Failures throw a typed `MediaError` (kinds include the generalized `source_key_*`, `duplicate` with `existingId`, `gone`, `timeout` for create at 15 s); nothing is queued.
- Keep the optimistic layer simple: toggles may update the cache optimistically with rollback on error; the shelf's per-row layering (`hooks.ts` layers, `OverlapMutations.test`) is over-built and must not be restored as is (see 12).
- Pure modules with unit tests: `filters.ts`, `sort.ts` (`Intl.Collator(locale, {sensitivity:'base', numeric:true})`, id tie-break), `search.ts`, `counts.ts`, `duplicates.ts` (`normalizeIsbn`, `titleKey`, `findByLink`, `findByIsbn`, `titleInLibrary`), `sourceUrl.ts` (`draftLink`, `draftText`, `safeHttpsUrl`, `coverTapUrl`), the last two reading the shared vectors.
- State: `localStorage` per list keyed by user id (`rwx.filters.books`...), unreadable -> default.
- Add sheet shell: title field, ONE entry list ending with the draft entry built locally with `draftLink`, create is always `create({id, sourceUrl})`; draft entry hidden when `titleInLibrary`, plain "Already in your library" line if nothing is left; failed create keeps the sheet open and retries the same id; `providerEntries` slot filled by `media-search`.
- Navigation: bottom tab bar Books/Movies/Settings, tab in the URL hash, panes mounted once and then kept (shelf `AppShell`); `App` renders the shell instead of `SettingsScreen` directly.

## 11. Create flow (draft path; provider URLs in `media-search` design section 12)
`BookService.create(userId, id, sourceUrl)` (not transactional at the top level, so a later provider call never runs under the lock):
1. Read (no lock) the row `(userId, id)`: live -> 200 with it, no URL inspection; tombstone -> 410.
2. `drafts.identify(sourceUrl)` (`@Qualifier(MediaResolver.DRAFT) MediaResolver<BookRef, BookItem>`): empty -> 400 `validation` on `sourceUrl` (media-search replaces this branch by the provider catalog).
3. `drafts.resolve(userId, ref)` -> `BookItem` (title = normalized text, link rebuilt); `externalId = TitleKey.of(title)`.
4. One short transaction: `UserLock.lock`, repeat step 1, duplicate checks (section 3), insert (`planned`, not favorite, version 1), 201. A lost race resolves to 200 (same id) or 409 (another id), never 500.
Movies: the same, type `movie` for drafts. Only `media` imports the draft qualifier; drafts are never in `/data-sources`.
Client twin: the add sheet's draft entry uses `draftLink(text)`; the same string is what the server rebuilds, so `externalLink` equality works.
