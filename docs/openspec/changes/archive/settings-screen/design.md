# Design: settings-screen

## 1. Decisions
| Question | Decision | Why |
|---|---|---|
| How is Settings entered? | Phase 2: it is the only screen after sign-in; `App` renders `SettingsScreen` directly for a signed-in user (no router, no tab bar, no navigation chrome). One screen with inline sections, no sub-navigation; the content column is capped (`max-w-xl`) and centered so wide screens do not stretch the rows. Phase 3 (`media-core` F8): the bottom tab bar (Books, Movies, Settings; Reminders joins in its phase, 4 tabs max, `design-system.md`) makes this screen the Settings tab with no change to the screen itself. | There is nothing else to navigate to in Phase 2. Two-taps rule stays true later: Settings is one tap from any list. A header gear icon was rejected: a second entry pattern next to the tab bar. |
| Where do timezone/locale writes go? | Superseded by `settings-module`: `PATCH /api/v1/settings` through a settings hook; `Me` no longer carries `timeZone`/`locale` and `PATCH /me` is gone. | The old answer (`PATCH /me` through `useUpdateSettings`) no longer exists in the contract. |
| Effective UI locale | `settings.locale` once loaded, `detectLocale()` before that, on failure and on the login page (the stored locale is never null since sign-up fixes it), via a `useLocale()` hook used by `App` and every screen (replaces the per-component `detectLocale()` calls). `document.documentElement.lang` follows it. | The stored locale is the user's explicit choice and applies on all devices; it is set at sign-up from the browser language, so there is no null case. |
| Language control | A native select row (label left, value right) in the same group as the timezone ("Language and timezone"): English, Русский, Українська, each shown in its own language, the effective one selected. No "device default" option. | The contract's `locale` enum has no null write, so a choice cannot be undone; backend change not allowed here. The server seeds the locale at sign-up (Accept-Language), so the UI starts in the browser language and the user can change it. |
| Timezone auto-detection | Once per app load and user: if stored `timeZone === 'UTC'` (the default of a new account) and the device zone differs from `UTC`, PATCH the device zone. Never overwrite a non-UTC value. | Matches "first sign-in" in the spec and removes the silent overwrite of a user-chosen zone by a device in another zone (travel, second device). |
| User explicitly chose UTC | On an explicit UTC choice the client stores `rwx.tz.chosen.<userId>=1` in localStorage; the detection skips when it is set. When the stored zone is already `UTC` and the device zone differs, a text action "Keep UTC on this device" sets the same flag (no request) and hides itself. | Without it a deliberate UTC would be overwritten at next open. The flag is device-local; a second device would redetect once (accepted, documented, no server field available). |
| Timezone control | A row in the same group: native `<select>` of `Intl.supportedValuesOf('timeZone')` plus `UTC`, with the current value preselected, and a "Use this device's timezone (X)" button when the device zone differs from the stored one. | Native pickers are best on iOS, no search widget to build; ~400 entries are fine. Server stays authoritative: unknown id gives 400 `invalid_timezone`, shown inline and the select reverts. |
| Export | `api.GET('/api/v1/me/export', { parseAs: 'blob' })`, file name from `Content-Disposition` (fallback `rwx-export-YYYY-MM-DD.json`), saved through an object URL and a temporary `<a download>`. Spinner while pending, inline error on failure. | One tap per `INTERACTIONS.md`. The response may contain license keys: the blob is never stored or logged, the URL is revoked ~5 s after the click (iOS may read the blob late). On the installed iOS PWA the system may show a preview/share sheet instead of saving; accepted, verify on device. |
| Delete account | Danger row opens an `alertdialog` (permanent, all data removed; Cancel focused, Escape cancels). Confirm calls `DELETE /api/v1/me` (CSRF via the shared client). On 204: clear the query cache, remove device-local `rwx.*` localStorage keys, raise the signed-out signal (landing page), like `useLogout`. On failure the dialog stays open with an inline error. A 401 means already signed out (same landing). | Only destructive action with a dialog (`INTERACTIONS.md`). |
| Sources section | `features/settings/SourcesSection.tsx` (filled by `datasource` DS-F4), rendered between Account and Language and timezone. | One file, no registry framework. |

## 2. Structure (frontend/src/features/settings)
`SettingsScreen.tsx` (grouped-list layout, tokens from `design-system.md`), `AccountSection.tsx`, `RegionSection.tsx` (group) with `LanguageSection.tsx` (`LanguageRow`) and `TimezoneSection.tsx` (`TimezoneRows`), `components/SelectRow.tsx`, `AccountDataSection.tsx` (+ `DeleteAccountDialog.tsx`), `SourcesSection.tsx`, `timezones.ts`, `useAccountData.ts` (`useExportData`, `useDeleteAccount`). Identity hooks stay in `features/identity` (`useMe`, `useLogout`; `features/settings/useSettings.ts` holds `useSettings`, `useUpdateSettings`, `useSyncTimeZone`, `useLocale`). Section order: Account, Sources, Language and timezone, Account data. Later sections (Notifications in the Push phase 6, Install in phase 5, About) slot in without reordering these. There is no notifications preference in Phase 2 (owner decision 2026-11-18): the flag, its column, its API field and the switch arrive with the Push phase, see `docs/openspec/changes/push-notifications/`.

## 3. i18n
New keys in the typed catalogue (`en.ts` defines the type; `ru.ts`, `uk.ts` must compile against it): `settings.title`, `settings.account`, `settings.signedInAs`, `settings.signOut`, `settings.signOutFailed`, `settings.region`, `settings.language`, `settings.timezone`, `settings.timezoneUseDevice` (placeholder `{zone}`), `settings.timezoneInvalid`, `settings.saveFailed`, `settings.data`, `settings.export`, `settings.exporting`, `settings.exportFailed`, `settings.delete`, `settings.deleteTitle`, `settings.deleteBody`, `settings.deleteConfirm`, `settings.cancel`, `settings.deleteFailed`, `nav.settings`. Language names are not translated. Strings must fit at 390px in ru/uk (buttons grow in height).

## 4. Edge cases
- Locale changed on device A: device B picks it up on its next `/settings` refetch; the UI switches without reload.
- Browser lacks `Intl.supportedValuesOf` (very old): fall back to a short list of common zones plus the current value; not a target browser, kept minimal.
- Sign out and delete both end in the signed-out state through `authSignal`; no router redirect needed.
- Double tap on Delete confirm: the button is disabled while pending.

## 5. Risks
`useSyncTimeZone` changes behaviour for existing test users (it no longer fixes a wrong non-UTC zone); acceptable, the Timezone section is the remedy.
