# Tasks: media-search
Prerequisites: `identity-github-oauth` B1-B3, B6 merged; frontend add flow needs `media-core` F2 and F7 (online-first, no Dexie) (the create contract is in `api/openapi.yaml`); F6 uses `PATCH /movies/{id}` for `seasonCount`/`tvStatus`. Backend tasks need no media-core code and no migration (V001 has `external_data_source_configuration`). Provider calls are stubbed with WireMock using recorded real responses in `src/test/resources/providers/`; this is the only allowed stub (external HTTP).

Verify: WireMock tests for timeout -> 504, 500 -> 502, 429 -> 503 + Retry-After, oversized body -> 502; limiter test: 31st search in a minute -> 429 with `Retry-After`.

- [ ] B3 Key management on V001 `external_data_source_configuration`: `listExternalDataSources`, `configureExternalDataSource` (format check, validate against TMDb before storing, upsert per user), `removeExternalDataSource`, derived `listSearchSources` status for `tmdb` (design section 2). Verify: valid key -> 201 and stored; TMDb 401 -> 422 and nothing stored; network error -> 504 and nothing stored; list/GET responses never contain the key (assert JSON and OpenAPI schema); delete then `tokenSaved=false`; key absent from `toString` and captured logs.
- [ ] B4 TMDb `searchMovies` and `getMovieDetails` (`language` = user locale, en fallback, also part of the cache key): multi-search without people, 10 max, mapping, image size selection with cached `/configuration`, movie/tv credits rules, TV status mapping, 409 `tmdb_token_missing`/`_invalid` (401 sets the in-memory `rejected` marker, network error does not). Verify: WireMock fixtures per rule, including Canceled -> ended, null -> absent; the request carries `language=ru` for a ru user and `en` when locale is null; the same query for ru and en users does not share a cache entry.
